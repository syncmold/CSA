# 範本、簽核流程與內控依據透過與 Claude 對話寫入草稿，不做匯入介面

稽核部提供的新問卷、新簽核名單與內控文件格式不固定（Word、PDF、掃描檔、Excel 都有），所以系統不做固定格式的匯入功能，也不內建 AI；改由開發者把檔案交給 Claude，Claude 分析後直接把內容寫成草稿，再由稽核管理者在系統畫面上檢查並按「啟用」才生效。這樣不用為每種來源格式開發解析器，也不用負擔 AI API 費用；人工啟用這一步則擋住 Claude 解析錯誤造成的錯誤流程或錯誤對照。

## Consequences

- 新增範本或流程需要開發者參與，稽核部無法完全自助；手動情況可改用系統內的流程編輯器。
- 資料庫需要一條供 Claude 寫入草稿的受控途徑，且只能寫入草稿狀態。

## 修訂

- 2026-11-11（Q127）：內控依據從畫面與 PDF 拿掉，對話寫入內控文件與內控依據（#39）不做；範本與簽核流程照本 ADR。
- 2026-11-18（Q137 (7) ①，#202；🟡 暫行做法，使用者同意先用，尚未定案）：範本拿掉版本與草稿、簽核流程拿掉狀態，「寫成草稿」不再成立。對話寫入改成只能寫入資料庫還沒有的範本編號，以及停用範本還沒有流程的「範本 × 廠區」（流程沒有狀態，寫給啟用中的範本就等於直接能發起，所以擋下）：範本寫成停用，稽核主管在範本管理檢查後改為啟用（取代原本的「按啟用才生效」）；流程沒有狀態，靠發起檢查與年度發起時人工勾選把關。已有的擋下（42501），請到範本管理／簽核流程直接修改。受控途徑（`csa_drafter`、`draft_template`／`draft_route`、`guard_draft_path`）保留，觸發器改成只放行這個交易新建的範本與流程底下的資料。
