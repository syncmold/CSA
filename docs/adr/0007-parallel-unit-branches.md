# 各自評單位分流並行，全部核准後才匯流到廠區經理人

2026-11-02 起，自評表在廠區端不再一關接一關：範本用到的每個自評單位各走一條分流（自行檢查人員 → 部門主管），各單位同時填寫、各自送本單位主管；所有分流都核准後才匯流到廠區經理人，之後稽核室三關照舊依序覆核。ADR 0003 選一條直線，理由之一是「符合紙本的傳遞習慣」；使用者確認紙本一個單位接一個傳遞只是因為紙本只有一份，各單位的控制要點互不干擾，改成線上就該讓它們同時進行，縮短整張表的完成時間。仍是一份自評表、每人只能答本單位的控制要點，這部分不變。

## Considered Options

- **維持一條直線（ADR 0003）**：狀態最簡單，但後面的單位要等前面的單位簽完，整體耗時最長，而且這個順序在線上沒有實際意義。
- **每個自評單位拆成獨立的自評表**：並行最徹底，但整體結論、簽核欄與 PDF 會被拆散，不再對應一份紙本；分流並行已經拿到「同時進行」的好處，不必付這個代價。

## Consequences

- 一張自評表匯流前會同時停在好幾關，「目前在第幾關」不再是一個數字：看得到誰、能改什麼、停留天數、追蹤總覽、首頁待處理、退回與加簽都要改以分流為單位計算。
- 退回可以只重開一條分流，其他單位不受影響。
- 既有的一條直線自評表要以 migration 轉成分流；部署前打 tag `before-parallel-route` 並備份資料庫，主管若偏好舊版可以退回（Q116 (12)）。
